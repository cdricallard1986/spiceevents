# Back office — section « DJ » (équipe de la page Nos DJ)

Demande de Cédric (13/11/2026) : « ajoute la liste des DJ dans le back office avec le texte, la photo etc. »

## Décisions

- Les DJ de l'équipe et les musiciens (aujourd'hui Antoine D., Kevin R., DJ Pan's, David G., Lucas M., Angel)
  passent du code (`contenu/pages/nos-dj.ts`) à la table `equipe`. Le fondateur (Cédric) reste dans le code :
  sa section a sa propre mise en page et renvoie vers « À propos ».
- Même modèle que les avis, pour que le back office reste homogène : liste avec flèches d'ordre, modale
  auto-enregistrée, création non publiée, publication et suppression confirmées.
- Bilingue champ par champ (vide en anglais = texte français), noms de famille réduits à l'initiale (règle de Cédric).
- Photo : envoi direct navigateur → Storage (`medias/equipe/<aaaa>/<mm>/…`) par URL signée, ou fichier du site
  (`/images/…`, pour les portraits déjà livrés). Point de cadrage choisi d'un clic sur la photo.
- Page publique : lecture des membres publiés (clé publishable, cache étiqueté `equipe`), repli sur le
  contenu du code sans Supabase dans l'environnement.

## Étapes

1. Migration `0012_equipe.sql` : table, contraintes, triggers `touch_updated_at` et `audit_trigger`, RLS
   (lecture publique des publiés, écriture `est_admin()`), import des 6 membres actuels (publiés).
   Compatible avec la production : l'ancien code ne lit pas cette table.
2. `lib/equipe/` : constantes, types, schéma Zod (TDD), conversion ligne → carte de la page (TDD), lecture
   en cache + repli.
3. Server Actions `app/admin/(espace)/dj/actions.ts` (garde + Zod + client de session + `revalidateTag`), testées.
4. Page `/admin/dj`, composants `GestionEquipe` et `FicheMembre` (photo : zone de dépôt, icônes sur l'image).
5. Menu (section « DJ »), audit RLS (lecture des non publiés refusée au visiteur, écritures refusées).
6. Page publique Nos DJ lue en base.
7. Vérifications : tsc, ESLint, Vitest, rendu réel (bureau et 390 px), puis version, commit, push `dev`.
